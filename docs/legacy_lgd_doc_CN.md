# Legacy LGD 文件文档

> [!NOTE]
>
> 本文描述的是 **PC 老引擎**（以 AS2C 为节点，2010 年前的 Sigma 游戏）自带的 lgd 格式。
>
> 它和 `lgd_generator.exe` / `lgc_compiler.exe` 产出的 lgd **不是同一种格式**，两者互不兼容。为了区分，本文把前者称为 **Legacy LGD**，后者称为 **新版 LGD**。

## 概述

省流总结：**Legacy LGD 是脚本编译结果在内存里的样子，原样 dump 到磁盘的产物。**

目前能找到的导出代码只有地图编辑器里的 `Save()`。官方是否另有独立编译器，我们不知道，只能说从来没有流出过。它的格式也不像专门设计过的。引擎在内存里有三样东西：

1. **字面值表**（也许叫栈对象表更加合理）：所有变量、参数的初始值
2. **符号表**：变量名、函数名及其元数据
3. **字节码**

Legacy LGD 就是把这三样按顺序写出来。读取时再原样读回去，跳过编译这一步。

> [!IMPORTANT]
>
> **lgc 在正常加载时不会先变成 lgd 文件。** 两条路径的终点都是这三样内存结构，执行器只认内存：
>
> ```
> .lgc ──(运行时编译)──┐
>                      ├──► 字面值表 + 符号表 + 字节码（内存）──► 执行器
> .lgd ──(反序列化)────┘
> ```
>
> lgd 只是这份内存结构的“存档”。正常加载流程里，引擎不会把编译结果写回磁盘：`Save()` 在反编译代码里没有任何调用点。

> [!NOTE]
>
> 据目前掌握的样本，官方实际发行 Legacy LGD 的只有 **ru 版的 Crazy Launch**，暂不知道这么做的原因是什么。其余 PC 发行版带的都是明文 `.lgc`。
>
> 其格式和 AS1 引擎相同，本文的分析也会重点基于这个版本。
>
> ZS1 引擎读写的也是这种格式，但它的编译器是升级版：支持函数前置声明（`Foo();`），还多了 `ActionN` / `ScriptEventN` 映射表。所以 ZS1 的脚本用 AS1 编译器编不过；就算编出来，lgd 也不保存这两张映射表，加载后地图触发器和 `ScriptEventN` 的联动会断开。
>
> 另外，不同引擎的格式略有不同，如时间充裕可在下文中讲述。

对于引擎来说，`.lgc` 和 `.lgd` 都能被识别，两者同时存在时优先读取 `.lgc`。

## 第一部分：字面值表 (Literal Table)

### 1. 格式

每个变量、数组元素、函数参数、局部变量各占一个条目。

其格式为 `Flag | Value`，若未初始化，就只记录一个 Flag。

和新版相比，没有 `Size` 和 `ID` 字段，非常的 simple。数组长度、归属关系全部由第二部分的符号表记录。

| **偏移** | **字段** | **长度** | **说明** |
| --- | --- | --- | --- |
| `0` | **Flag** | 1 byte | 类型 / 状态位 |
| `1` | **Value** | 0 / 4 / n+1 bytes | 仅当被初始化后才存在。int 为 4 字节，string 为 XOR 0x17 后以 `00` 结尾的字符串 |

### 2. 例子

#### extern func

```c++
extern MessageText(string text, int x, int y, int fontNvid = -1) 65;
```

```c++
01                      // para string text
42                      // para int x
42                      // para int y
0A FF FF FF FF          // para int fontNvid = -1
```

#### int array

```c++
int partArray[4] = { 1, 2 };
```

```c++
0E 01 00 00 00          // partArray[0] = 1
0E 02 00 00 00          // partArray[1] = 2
46                      // partArray[2]
46                      // partArray[3]
```

#### str array

```c++
string strArrayInit[3] = "x";
// AS1 独有写法：标量初始化整个数组，放其他版本就会报错
```

```c++
05                      // strArrayInit[0]
05                      // strArrayInit[1]
0D 6F 00                // strArrayInit[2] = "x"
```

### 3. Flag 标志位

与新版 LGD 旧格式的 Flag 相比：

1. **没有 `0x80` 基准位。** 到了 AS2-Addon 和 ZS2，lgd 里才保留 `0x80`。
2. **未初始化的 string 没有 `0x40`。** int 的未初始化位倒是有的。从 AS2 原版起，未初始化的 string 也带 `0x40` 了。

## 第二部分：符号表 (Symbol Table)

紧跟在字面值表之后。头 4 字节是符号数量，随后每个条目是 **明文名字** + **定长属性块**。

> [!IMPORTANT]
>
> 和新版不同，Legacy LGD 的**符号名不加密**，就是明文 ASCII + `00`。

### 1. Type 取值

| Type | 含义 |
| --- | --- |
| `1` | 全局变量 |
| `2` | extern 函数 |
| `3` | 脚本函数 |
| `4` | goto 标签（已定义） |
| `5` | goto 标签（仅被引用、尚未定义，编译期中间态） |

### 2. 20 字节属性块 + 文本区

| **偏移** | **长度** | **字段** | **说明** |
| --- | --- | --- | --- |
| — | n+1 | **Name** | 明文，`00` 结尾 |
| `+0` | 1 | **Type** | 见上表 |
| `+1` | 3 | 填充 | 样本中为未初始化的内存残留，**垃圾数据** |
| `+4` | 4 | `def_str` 指针 | 内存里 `STRING` 对象的指针值（样本中多为 `80 75 41 00`），**垃圾数据** |
| `+8` | 4 | **V0** | Type 1：变量在字面值表的**起始下标**<br/>Type 2：**extern 编号**<br/>Type 3：函数在字节码段内的**入口偏移** |
| `+12` | 4 | **V1** | Type 2 / 3：参数在字面值表的**起始下标**<br/>Type 1：样本中为无意义的指针值（如 `A0 38 40 00`） |
| `+16` | 4 | **V2** | Type 1：数组长度（单变量为 1）<br/>Type 2 / 3：参数个数 |

所有符号条目之后，是一个**文本区**：`symbol_count` 个 `00` 结尾的字符串，对应每个符号的 `def_str`，一般都是 `00`。

### 3. 例子

#### extern func

```c++
extern MessageText(string text, int x, int y, int fontNvid = -1) 65;
```

```c++
4D 65 73 73 61 67 65 54 65 78 74 00         // MessageText
   02                                       // Type 2：extern 函数
   00 00 00                                 // 填充（内存残留）
   DC 2C E0 00                              // def_str 野指针（垃圾）
   41 00 00 00                              // V0 extern 编号 65（字节码里的 opcode 0x41）
   00 00 00 00                              // V1 参数栈起点 [0]
   04 00 00 00                              // V2 参数个数 4
```

#### func

```c++
ScriptEvent1(int a, int b, int c)
{
    gval = a + b + c;
}
```

```c++
53 63 72 69 70 74 45 76 65 6E 74 31 00      // ScriptEvent1
   03                                       // Type 3：脚本函数
   00 00 00                                 // 填充（内存残留）
   DC 2C E0 00                              // def_str 野指针（垃圾）
   35 00 00 00                              // V0 字节码入口 +0x035
   2D 00 00 00                              // V1 参数栈起点 [45]
   03 00 00 00                              // V2 参数个数 3
```

#### array

```c++
int intArray[3] = { 114, 514, 19198 };
```

```c++
69 6E 74 41 72 72 61 79 00                  // intArray
   01                                       // Type 1：全局变量
   00 00 00                                 // 填充（内存残留）
   DC 2C E0 00                              // def_str 野指针（垃圾）
   0F 00 00 00                              // V0 栈起点 [15]
   E8 EB D8 00                              // V1 垃圾
   03 00 00 00                              // V2 元素个数 3
```

## 第三部分：字节码 (Bytecode)

**全程明文，不加密**，`PUSH_STR` 里的字符串也是明文。

操作码和操作数大差不差，但是各个引擎之间有差别，有空再讲。
